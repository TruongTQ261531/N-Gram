# Supplemental common-wall profile (declared before its measurements)

The original three-repeat run remains unchanged. Its observed query308
hits RSA-FD's one-million-node cap before using the120-second wall guard,
while JAA-FD completes. An arrangement-node counter is not the same unit
of work in the two algorithms. Do not interpret that cap alone as a
wall-budget superiority result.

Run a separate retrospective **single first pass on ALL128 IDs** and all
four controls, with exactly the same scorer/channel/target/source. Disable
only the finite adapters' arrangement-node guard, retaining the common
120-second soft whole-pipeline guard and50million state-score-cell cap.
No algorithm, pruning heuristic, domain or other parameter is changed.
Hash-rotate method order with seed-stringutk-wall-only-v1; one numerical
thread, sequential, only a shared warm immutable index. Source validation
and other benchmarks must finish before this profile begins. One execution
per method/query gives descriptive first-pass cost, not a median of three
or a new primary/confirmatory significance test.

Retain every default measurement and every profile unknown/error. The
profile runner never opens old outcomes to choose queries or change routing.
Reference receipts may be joined only after measurement. The full default
archive already contains identical immutable factors/regional proofs on
completed queries; publish cryptographic links to these to avoid duplicating
large coefficient/filter tables. Retain profile states, RSA witnesses/JAA
cells and exact unions; check their membership against the same independently
replayed all-state/full-corpus oracle. If a profile completes a query for
which neither default adapter has an exact factor receipt, retain its full
new receipt rather than silently assuming identity.

This is an explicitly supplemental resource-profile analysis prompted by
default cap behavior. It neither overwrites the original freeze/results nor
creates independent evidence on unseen queries. Ratios only compare completed
same-target pairs; complete denominators and costs spent on unknowns remain
visible. No global/original-C++ performance or Q1 guarantee is inferred.
